# Medal Pusher

three.js（描画）+ Rapier（物理）+ React（UI）で作った、ブラウザで動くメダルゲーム（コインプッシャー）。

## 動かす

```bash
npm install
npm run dev
```

> `node_modules` は入っていません（Vite/Rolldown はプラットフォーム固有のネイティブバイナリを
> 使うため、こちらでインストールしたものは Windows では動かないので同梱していません）。
> `_to_delete/` フォルダにはこちらで作った古い成果物が入っています。丸ごと削除して構いません。

```bash
npm run build      # dist/ に静的ファイルを出力（相対パスなのでそのまま配信可）
npm run preview
npm run typecheck  # UI（TypeScript）の型チェック
```

## 構成

| | |
|---|---|
| `src/game/`, `src/physics/`, `src/core/` | ゲーム本体。素の JavaScript |
| `src/ui/` | HUD と演出。**React + TypeScript** |
| `src/ui/mount.tsx` | 両者の唯一の境界。ゲームループは React を知らない |

UI の状態は `src/ui/store.ts` の小さな外部ストアを `useSyncExternalStore` で購読しています。
ゲームループは毎フレーム書き込んでよく、**値が実際に変わったときだけ**再レンダリングが走ります
（詳細は DESIGN.md §6.5）。

## 操作

| 操作 | 内容 |
|---|---|
| マウス移動 / ← → | 投入位置を動かす |
| クリック / Space | メダルを投入（長押しで連続投入） |
| 右ドラッグ / ホイール | 視点回転 / ズーム |
| **M** | 消音の切り替え |
| **D** | デバッグパネル（物理・抽選パラメータ調整、抽選の強制実行、コライダー表示） |

## 遊び方

持ち枚数 **300枚**から始まります。投入すると1枚減り、払い出し口に落ちるたび1枚増えます。
0枚になって8秒間なにも落ちてこなければゲームオーバーで、「もう一度」で300枚から再開できます
（フィールドのメダルは筐体の在庫なのでそのまま残ります）。

フィールドに光る**ボールが常に3個**転がっています。メダルと一緒に押し出して手前の払い出し口に
落とすと、8種類の絵柄の**スロット**が回ります。3列揃えばアタリで、絵柄に応じた枚数のメダルが
降ってきます（配当は画面上部の PAY TABLE を参照）。
サイドポケット（手前左右の赤いライン）に落ちた場合はハズレで、抽選は回りません。
ボールは落ちてから約1.6秒で上段に戻り、そこから2.2秒はその場で静止します
（戻った勢いでそのまま落ちて連続で抽選が回るのを防ぐため）。

スロットの絵柄構成と出現比率は
[この記事](https://qiita.com/hunyu/items/4547d1d9fb734d81d189) を参考にしています
（配当枚数とハズレ比率だけこの筐体に合わせて調整。理由は DESIGN.md §7.4）。

## 触るところ

パラメータは `src/config.js` に集約してあります。手触りを変えたいときはまずここ。

- `pusher.strokeHalf` — **払い出し量に最も効く**。小さくすると渋くなる
- `slot.symbols[].pay` / `.weight` — スロットの配当と出現比率
- `wallet.start` — 持ち枚数の初期値（300）
- `ball.count` — フィールドに出しておくボールの数
- `ball.spawnZ` — ボールを戻す位置。抽選の頻度がほぼこれで決まる（前寄りほど頻繁）
- `ball.settleSeconds` — 戻った直後に静止させる時間
- `ball.friction` — 高いとメダルの山に食い込んで落ちてこなくなる
- `audio.impactThreshold` — 衝突音の鳴りやすさ。下げすぎると鳴りっぱなしになる
- `medal.friction` — 山の崩れ方。低い＝サラサラ流れる / 高い＝固まる
- `medal.maxCount` — 同時に存在するメダルの上限（585）。ただし**枚数と物理の重さはほぼ比例**します
  （200枚→5ms / 300枚→10ms / 400枚→16ms / 500枚→24ms。60fps の予算は16.7ms）。
  通常プレイでは払い出しと釣り合って 160〜230枚に落ち着くので、上限は余裕として置いてあります
- `hopper.fieldLimit` — ホッパーが場内を埋める上限（330）。ここが実質的な「重さの天井」
- `layout.tableFront.rx` — 落とし口の登り勾配。0 にすると水平に戻ります
- `layout.pusherLip` — 上段の縁の壁。`gap`（中央の開口）を狭めすぎると上段に溜まって詰まります
  （開口3.0で払い戻しが59%まで落ちました。DESIGN.md §7.7）

セーブデータの設計（未実装）は DESIGN.md §12 にあります。

設計の詳細と、実装中に判明した落とし穴は [DESIGN.md](./DESIGN.md) に書いてあります。

- §2.4 なぜプッシャーが背面壁に潜り込んでいるのか（外すと払い出しが止まります）
