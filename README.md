# Medal Pusher

three.js（描画）+ Rapier（物理）+ React（UI）で作った、ブラウザで動くメダルゲーム（コインプッシャー）。

## 動かす

```bash
npm install
npm run dev
```

> `node_modules` は入っていません（Vite/Rolldown はプラットフォーム固有のネイティブバイナリを
> 使うため、こちらでインストールしたものは Windows では動かないので同梱していません）。
> `_to_delete/` フォルダにはこちらで作った古い成果物が入っています。丸ごと削除して構いません。

```bash
npm run build      # dist/ に静的ファイルを出力（相対パスなのでそのまま配信可）
npm run preview
npm run typecheck  # UI（TypeScript）の型チェック
```

### GitHub Pages に置く

`main` に push すると `.github/workflows/deploy-pages.yml` がビルドして公開します
（手動実行も可）。**最初に1回だけ**、リポジトリの
**Settings → Pages → Build and deployment → Source** を「**GitHub Actions**」に
変更してください。公開先は `https://<ユーザー名>.github.io/<リポジトリ名>/` です。

`vite.config.js` の `base: './'` により出力が相対パスになっているので、
サブディレクトリ公開でもパスの書き換えは要りません。

フィーバーの映像（`src/vid/fever_1.mp4`、12.1MB）もビルド出力に入ります。
公開物がそのぶん大きくなりますが、読み込みは起動と並行なので、
間に合わなければ液晶がいつもの背景のまま進むだけです。

## 構成

| | |
|---|---|
| `src/game/`, `src/physics/`, `src/core/` | ゲーム本体。素の JavaScript |
| `src/ui/` | HUD（持ち枚数・配当表・計測値・ゲームオーバー）。**React + TypeScript** |
| `src/game/SlotDisplay.js` | スロットの演出。筐体前面の液晶として 3D シーンの中に描く |
| `src/ui/mount.tsx` | 両者の唯一の境界。ゲームループは React を知らない |

UI の状態は `src/ui/store.ts` の小さな外部ストアを `useSyncExternalStore` で購読しています。
ゲームループは毎フレーム書き込んでよく、**値が実際に変わったときだけ**再レンダリングが走ります
（詳細は DESIGN.md §6.5）。

## 操作

| 操作 | 内容 |
|---|---|
| クリック / Space | **メダルを発射**（狙いは自動で首を振る。長押しで連射） |
| 右ドラッグ / ホイール | 視点回転 / ズーム |
| **M** | 消音の切り替え |
| **D** | デバッグパネル（物理・抽選パラメータ調整、フィーバー突入、JP 発火、クルーンの当選率測定、コライダー表示） |

スマートフォン（iPhone Safari で確認）では次のようになります。

| 操作 | 内容 |
|---|---|
| 1本指でタップ / 長押し | **メダルを発射**（PC のクリックと同じ） |
| 2本指 | 視点回転 / ズーム |
| 右下の SOUND | 消音の切り替え |

**台の中身は PC と同じです。** 物理のパラメータも当選率も発射の初速も 1bit も変えていません
（実測で突き合わせた表は DESIGN.md §13.1）。変えているのは描画品質と HUD の並べ方だけです。

縦持ちでは筐体が画面の中ほどに来て、上下の空きが HUD の置き場になります。横持ちは PC と同じ配置です。
PC から見た目を確かめたいときは `?device=mobile` を付けてください（`?device=desktop` で逆も可）。

## 遊び方

持ち枚数 **300枚**から始まります。投入すると1枚減り、払い出し口に落ちるたび1枚増えます。
0枚になって8秒間なにも落ちてこなければゲームオーバーで、「もう一度」で300枚から再開できます
（フィールドのメダルは筐体の在庫なのでそのまま残ります）。

### 撃ち込む — 投入はタイミング

メダルは上から落ちてきません。**手前の発射口から上段のデッキへ撃ち上げます。**
発射口の狙いは一定の速さで左右に首を振り続けていて、プレイヤーが決めるのは
**撃つ瞬間だけ**です。着地点のリングと弾道のガイドが常に出ているので、
それが乗ってほしい場所に来た瞬間に押します。

- 首振りの中央で撃つと**デッキの最奥（背面壁ぎわ）に乗る**。山の一番後ろから押されるので、
  戻ってくるまで長い
- 端で撃つと**左右の手前寄り**に乗る。すぐ押し出されるかわりに、山はほとんど育たない
- 長押しの連射は「とりあえず撒く」用。狙って1枚ずつ撃つかは自分で決めます

### チャッカーを狙う

払い出し口の先は手前に下る**坂**になっていて、そこに穴が3つ開いています。
撃ち込む位置が最後にここへ効いてくるので、狙う価値があります。

| 穴 | 場所 | 入るとどうなるか |
|---|---|---|
| **START**（水色）| 中央 | **スロットが1回まわる。** そのメダルは飲まれてクレジットにならない |
| **CHANCE**（橙）×2 | 左右 | **フリッパーが8秒開いて** START に入りやすくなる + JP が少し増える |

スロットの盤面は **3列 x 3段**。有効ラインは 上段 / 中段 / 下段 / 斜め2本 の **5本**で、
同じ絵柄がライン上に3つ並べばアタリです。1回で複数ラインが揃うこともあり、
払い出しは **1ラインあたりの枚数 × 揃ったライン数 × 倍率**。
絵柄は8種類で、**青7だけはジャックポット当選**です。

保留（配当表の下のランプ）が満杯のときにさらに入賞すると、
捨てられる代わりに **ODDS が ×2 → ×3 → ×5** と上がり、当たったときの枚数に掛かります。

### 演出は色で期待度を示す

実機と同じく **白 → 青 → 緑 → 赤 → 金 → 虹** の順に期待できます。
賑やかしではなく、結果を先に決めてから色を引いているので**信頼度が実際に一致**します。

| 色 | 信頼度 | 出るもの |
|---|---|---|
| 白 | 8.6% | 無演出 |
| 青 | 36.2% | 予告音 + 青枠 |
| 緑 | 59.9% | 緑枠 + 擬似連（止まりかけて再始動）|
| 赤 | 76.0% | 赤枠 + カットイン |
| 金 | 85.7% | 金枠 + 擬似連2回 + カットイン |
| **虹** | **100%** | 虹枠 + **フリーズ**（全部止まる）|

金や虹は「当たる」だけでなく「**大きい**」ことも示唆します（バー以上ほど出やすい）。
ハズレのリーチでは、当たり絵柄を一瞬見せてから1つずらす**滑り**が入ります。

### フィーバー（ボール3個）

フィールドに光る**ボールが常に3個**転がっています。手前の払い出し口に落とすと **STEP が1つ**進み、
**3つでフィーバー（25秒）**です。液晶で数字が動くだけの演出ではなく、**台そのものが変わります**。

- 落とし口の**勾配が反転**して、山ごと手前に流れる
- プッシャーの**ストロークが拡大**する
- **サイドポケットが塞がって**ロストがゼロになる
- 筐体の液晶の**背景に映像が流れます**（音つき。`src/vid/fever_1.mp4`）

実測で払い出しは通常の **2.7倍**（25秒で71枚）になります。
サイドポケットに落ちたボールはハズレで、STEP は進みません。

### 3段クルーン（固定500枚）

筐体の中、盤面の左手前に**3枚の皿**が並んだ役物が吊ってあります。
払い出し口にボールが落ちると、その球が払い出し口の開口から機械の中へ入り、
リフトで持ち上がって1枚目の皿に落ちます。皿の底には**穴が5つ**、
そのうち**金の縁の1つが当たり**で、当たれば次の段へ。**3枚とも抜けると 500枚**です。

どの穴に入るかは決めていません。**皿の上を転がる球の行き先を毎フレーム見ている**だけで、
乱数は投入時のばらつきにしか使っていません。実測で1皿あたり約 20%、3段抜けは
**約 1/130**（12000回で 1/135、別の 8000回で 1/123）。回っている時間は中央値 2.1秒・最長 7.3秒です。

払い出しは他の当たりと同じくホッパー経由で、500枚は場に降ってから押し出されます。

### UFO ボーナス（固定100枚）

ごく稀に、盤面の上空に **UFO** が現れます。**発射したメダルを直接当て続ける**と 100枚。
7秒しか居ないので、気付いてから撃ち始めるまでの間が勝負です。

浮かんでいる場所は適当ではなく、**発射口から見た水平距離が弾道の頂点に固定**してあります。
弾道は首の角度まわりに回転対称なので、**首が UFO の方を向いた瞬間に撃てば必ず当たります**。
飛距離を読む必要はなく、読むのは向きだけ。底の板が金色に変わったら当たる向きです。

必要な直撃は 20発。リムのランプが20個並んでいて、当てるたびに1つ消えます。
1.2秒当たらないと1つ戻るので、当て続けないと落とせません。
押しっぱなしで撃つと 4.1発/秒 当たるので、**約5.2秒**。滞空の 7秒に対して
反応の余裕は 1.8秒ほどです（実測は DESIGN_GIMMICKS.md §3.12）。

出現はメダル1枚の投入ごとに 1/2000。払い出しは他の当たりと同じくホッパー経由です。

### ジャックポット

液晶の左上のカウンタは、**投入・ロスト・CHANCE 入賞**で少しずつ増え続けます。
とくに**サイドポケットに落ちて失った1枚がそのまま JP に積まれます**。
スロットで**青7**を引くと、プッシャーが引っ込んで**メダルのタワーが積み上がり**、
それを押し崩して一気に払い出します。

スロットの絵柄構成は
[この記事](https://qiita.com/hunyu/items/4547d1d9fb734d81d189) を参考にしています
（配当枚数と比率はこの筐体に合わせて調整。理由は DESIGN_GIMMICKS.md §4）。

## 触るところ

パラメータは `src/config.js` に集約してあります。手触りを変えたいときはまずここ。

- `pusher.strokeHalf` — **払い出し量に最も効く**。小さくすると渋くなる
- `chute.slots[].dz0` — **チャッカーの入賞率はここで決まる。** 穴の奥行きがメダル直径 1.0 を
  またぐと頻度が桁で変わる（1.15 → 34回/分 / 0.92 → 9回/分 / 0.85 → 4回/分）。幅ではない
- `slot.symbols[].pay` / `.weight` — スロットの配当と出現比率。
  1回まわすのに1枚飲まれるので、**期待値が1枚を超えると増え続ける台になる**（実装値は 0.94枚）
- `fever.*` — フィーバーの長さと、その間のストローク・傾き
- `jackpot.perLost` — ロスト1枚あたりの JP 加算。ここが JP の主燃料
- `wallet.start` — 持ち枚数の初期値（300）
- `launcher.period` / `launcher.yawRange` — 首振りの速さと振り幅。**狙いの難しさはここ**
- `launcher.landZ` — 狙いの中央がデッキのどこに着地するか＝飛距離。初速はここから逆算される
- `kuruun.hole.count` — **クルーンの当選率はここ一箇所で決まる**。1皿あたりほぼ 1/count で、
  3段抜けはその3乗（5個 → 約1/130 / 4個 → 約1/53）。動かしたら必ず測り直すこと
  （デバッグパネルの「早送りで当選率を測る」で 1000回が一瞬で終わります）
- `kuruun.pay` — 3段抜けたときの払い出し枚数（500）
- `ufo.chancePerInsert` — **UFO の出現率。払い戻しに直結する唯一のつまみ**。
  期待値は `pay x chancePerInsert`（投入1枚あたり）で、1/2000 なら +5.0 ポイント
  （ホッパー経由なので手元に戻るのは7割ほど）。動かしたら払い戻しを測り直すこと
- `ufo.hits` / `ufo.lifeSeconds` — 必要な直撃数（20）と滞空時間（7秒）＝難易度。
  押しっぱなしで 4.1発/秒 当たるので、`hits / 4.1` が「最短で落とせる秒数」になります
- `ufo.decaySeconds` — 当たらない時間がこれだけ続くとダメージが1つ戻る（1.2秒）。
  0 にすると「合計で20発」になり、当て**続ける**必要が無くなります
- `ufo.arcFrac` — 弾道のどこに浮かべるか（着地までの割合）。0.46 が弾道の頂点。
  小さくするほど発射口に近づき、的の見込み角が広がって**狙う意味が薄くなります**
- `ball.count` — フィールドに出しておくボールの数
- `ball.spawnZ` — ボールを戻す位置。抽選の頻度がほぼこれで決まる（前寄りほど頻繁）
- `ball.settleSeconds` — 戻った直後に静止させる時間
- `ball.friction` — 高いとメダルの山に食い込んで落ちてこなくなる
- `audio.impactThreshold` — 衝突音の鳴りやすさ。下げすぎると鳴りっぱなしになる
- `audio.ballFallVolume` — 抽選ボールが落ちたときの音の大きさ。素材は
  `src/audio/ballFall/` に置いたぶんだけ自動で候補になる（増減してもコードは触らない）
- `medal.friction` — 山の崩れ方。低い＝サラサラ流れる / 高い＝固まる
- `medal.maxCount` — 同時に存在するメダルの上限（585）。ただし**枚数と物理の重さはほぼ比例**します
  （200枚→5ms / 300枚→10ms / 400枚→16ms / 500枚→24ms。60fps の予算は16.7ms）。
  通常プレイでは払い出しと釣り合って 200〜280枚に落ち着くので、上限は余裕として置いてあります
  （下段を広げたぶん、以前の 160〜230枚から増えています。DESIGN.md §7.10）
- `hopper.fieldLimit` — ホッパーが場内を埋める上限（330）。ここが実質的な「重さの天井」
- `layout.tableFront.rx` — 落とし口の登り勾配。0 にすると水平に戻ります
- `layout.pusherSideWall` — 上段の左右の壁。**手前には壁を付けないこと**。
  塞ぐと下段にメダルが降りてこなくなり払い戻しが36%まで落ちます（DESIGN.md §7.7）
- `layout.pocketX` — サイドポケットの口の広さ。ロストを減らすならここが効きます
- `layout.tableMain` / `layout.wallBack` / `layout.pusher` の z — 下段フィールドの奥行き。
  **3つを同じだけ動かすこと**。奥へ下げれば下段だけが広がり、上段デッキの奥行きは変わりません。
  広げると払い戻しが下がってロストが増えます（実測は DESIGN.md §7.10）
- `slot.display` — 液晶パネルの位置と大きさ。**背面壁の内面に貼ってあります**。
  下は上段の山（上端およそ 2.2）、上はカメラの画角（z=-2.92 では y=8.4 まで）に挟まれます。
  縦横比はテクスチャ（1024×501）と合わせること（DESIGN.md §7.9）
- `layout.frontGuard` — 手前の**見えない**壁。ガラスは描画コスト（1フレーム 1.71ms）のため
  外しましたが、コライダーは要ります。無いと弾かれたメダルが筐体の外へ抜けます（DESIGN.md §13.2）
- `render.fitWidth` / `render.fitHeight` / `render.maxFov` — 狭い画面で「最低でも映す箱」。
  縦持ちの見え方はここで決まる（16:9 より横長では効きません）
- `src/core/Device.js` の `QUALITY` — 端末ごとの描画品質。**ここに物理の値を足さないこと。**
  足した瞬間に PC とモバイルで別のゲームになります（DESIGN.md §13.1）

持ち枚数・通算成績・設定はブラウザの localStorage に自動保存されます（数百バイト）。
場のメダルは「何枚あったか」だけを保存し、並びは毎回作り直します。
記録の消去はゲームオーバー画面から行えます。詳細は DESIGN.md §11。

設計の詳細と、実装中に判明した落とし穴は [DESIGN.md](./DESIGN.md) に書いてあります。
特に次の2つは、知らずに触ると壊れるので目を通しておくことをおすすめします。

- §2.4 なぜプッシャーが背面壁に潜り込んでいるのか（外すと払い出しが止まります）
- §7.4 ボールを戻す位置と抽選頻度の関係（実測値つき）
- §6.5 UI に毎フレーム値を流すときの作法（素直に setState すると 60fps で再レンダリングします）
- §13 モバイル対応。**出しわけてよいもの / いけないものの線引き**と、iOS で踏んだ落とし穴
